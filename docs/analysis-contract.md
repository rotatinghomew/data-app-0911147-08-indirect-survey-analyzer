# 分析资料与解释边界

## 问卷机制
rr 版本的机制以 force_yes、force_no、truth 概率给出，总和为一；平台不保存个人随机分支。rr_joint 的 latent_states 和 response_states 声明潜在联合状态及可观察随机编码，transition 每行是给定潜在状态的响应概率。业务资料只保存 coded_answer，不保存潜在状态。list 版本记录基础条目数 k、实验臂 added_sensitive 与回答 count；只保存计数，不保存选了哪一项。allocation 指明随机到人还是到班。
## 推断对象
主结果是声明总体中的经历边际比例、共同发生比例或组间差异，不输出任何个人敏感状态。不同机制可能只支持联合分布的部分函数，需要按用户提出的查询判断；不得默认经历独立来制造联合点估计。可估、部分识别和不可识别的表示，以及估计方法由开发者设计。分析需区分机制已知与机制失真假设，并保留估计边界、不确定性及版本可合并依据；未经解释的零一裁剪不是有效推断。无响应与聚类随机化须进入适用性判断。
## 可核对资料
纯 truthful 的 rr 机制应退化为普通抽样比例；truth 为零时，回答没有提供敏感比例信息。名单实验中实验臂与对照臂的均值差有手算基准，但设计效应和顶底效应可能破坏解释。analysis_cases 提供只有两个边际机制而无联合信息、带联合编码、版本混合及计数越界输入；去掉唯一联合信息来源后，不应继续输出同等确定的共同发生比例。
